# M1: Reading — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn M0's unstyled list/detail into the reading experience from the Claude
Design canvas: themed Food/Drinks sides, grid and list browsing with search, filters and
sort, a recipe page with servings scaling and a tsp/metric toggle, photo-less recipes
that look intentional, and an installable PWA manifest.

**Architecture:** The backend gains three read-only pieces: an ingredient catalog
(`g_per_tsp` per ingredient, seeded into `/data/catalog/`), fuzzy search with rapidfuzz
behind `GET /api/recipes?q=`, and a route that serves a recipe's image files. The
frontend keeps one React tree for phone and desktop; CSS custom properties carry the
two side themes (`data-side` on the app root) and a 768 px media query switches between
the phone layout (bottom bar, filter sheet) and the desktop one (header, filter aside).
Filters live in the URL query; display preferences (grid/list, tsp/metric) live in
localStorage. All amount maths is in pure, unit-tested functions.

**Tech Stack:** as M0, plus `rapidfuzz` (Python) and `@fontsource/young-serif`,
`@fontsource/hanken-grotesk` (npm, bundled; no Google Fonts at runtime).

**Spec:** `docs/plan.md` (M1), `docs/requirements-v1.md` (1, 3, 4, 8, 9, 11, 13, 14,
15, 22, 23), the design canvas https://claude.ai/artifact/BueKAjP8pmy98iZUhn4WQY
(snapshot committed under `docs/design/` in Task 6), and `CLAUDE.md`.

## Global Constraints

- All M0 constraints still hold: port 8080, writes only under `/data` and `/tmp`, config only from `$APP_CONFIG`, no secrets, no host paths, logs to stdout.
- Sides `food`, `drinks`; categories food `mains, sides, desserts, sauces, prep`, drinks `cocktails, mocktails, syrups, prep`, shown capitalised ("Mains").
- Stored units stay metric (`g`, `ml`, `piece`, `dash`, `pinch`, `to taste`); tsp/tbsp exist only in display. 1 tsp = 5 ml, 1 tbsp = 3 tsp.
- Recipe `format_version` stays 1: M1 changes no stored recipe field. Computed fields (`g_per_tsp`) appear only in API responses.
- Catalog file `catalog/ingredients.json` carries its own `"format_version": 1`.
- Every interactive element is at least 44 × 44 px (the design's minimum); every icon-only control has an `aria-label`.
- Fonts: Young Serif (headings, recipe names, step numbers) and Hanken Grotesk 400/500/600/700 (everything else), self-hosted through `@fontsource`.
- Layout breakpoint: `(min-width: 768px)` is desktop. Phone artboards are 390 px wide with 16 px gutters; no horizontal page scroll at 360 px.
- The NAS already holds recipes, so new seed *recipes* would never reach it; M1 adds no seed recipes. The seed catalog is copied in when `catalog/ingredients.json` is missing.
- Work on `claude/peaceful-ptolemy-13s6fp` (reset to `origin/main` first; PR 1 is merged). Merging to `main` deploys and needs Serwan's OK.

## Review Focus

1. **Manifest behind Cloudflare Access:** the browser fetches the manifest without cookies unless told otherwise, gets Access's login redirect, and the app is not installable. `index.html` must use `<link rel="manifest" href="/manifest.webmanifest" crossorigin="use-credentials">`, and the server must send `application/manifest+json`. → Task 9 tests.
2. **Search input with accents, case and stray spaces** ("Crème", "  CHIKEN ", "creme brulee" vs "Crème brûlée"): same results as the plain query; an all-whitespace query is no query. → Task 2 tests.
3. **Scaling to awkward servings** (1 of a recipe for 4, 7 of 4, 24): no `0`, no `0.3333 piece`, no `1.0000001 g`; `no_scale` and `to taste` rows never change; unconverted `original` amounts are shown as written and flagged instead of being scaled. → Task 4 tests.
4. **Image route with hostile names** (`../recipe.json`, `%2e%2e/x`, `recipe.json`, `timeline.jsonl`, a name that is not the recipe's `image` or `source.photo`): 404, never a file outside the recipe folder and never the recipe's data files. → Task 3 tests.
5. **Stale or hand-written filter URLs** (`?cat=soups` on food, `?mark=bogus`, `?sort=rating`, a tag no recipe has): unknown values are dropped, never a blank page or a crash. → Task 5 tests.

### Task 2: Fuzzy search

**Files:**
- Create: `src/app/recipes/search.py`
- Modify: `pyproject.toml`/`uv.lock` (`uv add "rapidfuzz>=3.14"`), `src/app/api.py`
- Test: `tests/test_search.py`, `tests/test_api.py`

**Interfaces:**
- Produces: `search(recipes: list[Recipe], query: str) -> list[Recipe]` in `app.recipes.search` (best match first; M3's `search_recipes` MCP tool reuses it). `GET /api/recipes?side=<side>&q=<text>` returns `{"recipes": [...]}` in that order; without `q` (or blank `q`) the M0 behaviour is unchanged.

Matching: normalise text (NFKD, drop combining marks, casefold, split on non-alphanumerics). The words of a recipe are its name, ingredient items, tags and category. Every query word must match some recipe word: equal, the recipe word starts with it (at least 2 letters, for search-as-you-type), or `rapidfuzz.fuzz.ratio ≥ 80`. Order by: number of query words that hit the *name*, then the mean best score, then name.

### Task 4: Amounts (scaling, rounding, tsp)

**Files:**
- Create: `web/src/amounts.ts`
- Modify: `web/src/types.ts` (`RecipeIngredient extends Ingredient { g_per_tsp: number | null }`; `Recipe.ingredients: RecipeIngredient[]`)
- Test: `web/src/amounts.test.ts`

**Interfaces:**
- Produces:
  - `type UnitMode = 'spoons' | 'metric'`
  - `type AmountFlag = 'not-metric' | 'no-spoon-conversion' | null`
  - `formatAmount(ing: RecipeIngredient, factor: number, mode: UnitMode): { text: string; flag: AmountFlag }`. `text` is the amount column only ("250 g", "1½", "¾ tsp", "" for `to taste`).
  - `fraction(n: number): string` (quarters as `¼ ½ ¾`, e.g. `1.5 → "1½"`, `0.25 → "¼"`).

Rules (`factor = servings / recipe.servings`; `no_scale` and `to taste` rows use factor 1):
- `amount === null` with `original`: text is `original` unscaled, flag `not-metric`, whatever the mode.
- `to taste`: text `""` (the row reads "salt, to taste").
- `piece`, `pinch`, `dash`: below 1 → nearest ¼ (minimum ¼); 1 up to 3 → nearest ½; 3 and above → nearest whole. `piece` has no unit word; `pinch`/`dash` add theirs ("2 pinches" is not needed: "2 pinch" is fine).
- `g`, `ml` in metric: below 10 → nearest 0.5 (minimum 0.5); 10 up to 100 → nearest 1; 100 and above → nearest 5. Formatted without trailing zeros ("2.5 g", "250 g").
- Spoons mode converts small amounts only: `ml` → tsp = ml / 5; `g` with `g_per_tsp` → tsp = g / g_per_tsp. Convert when tsp ≤ 12 (4 tbsp). Below 3 tsp → nearest ¼ tsp (minimum ¼) "¾ tsp"; 3 tsp and up → nearest ½ tbsp "1½ tbsp". Larger amounts stay metric with no flag.
- Spoons mode, `g` without `g_per_tsp` and ≤ 30 g after scaling: metric text, flag `no-spoon-conversion` (requirement 8's flag, for Claude to fill the catalog later).

- [ ] **Step 1: Write the failing tests** with these exact cases:
  - `250 g ×1 metric → "250 g"`; `250 g ×0.25 → "60 g"` (62.5 → nearest 5); `6 g ×0.5 → "3 g"`; `3 g ×1/3 → "1 g"`; `0.4 g → "0.5 g"`.
  - `1 piece ×1.5 → "1½"`; `3 piece ×7/4 → "5"`; `1 piece ×0.25 → "¼"`; `2 piece ×0.3 → "½"`; `1 piece ×0.1 → "¼"`.
  - `30 ml spoons → "2 tbsp"`; `2.5 ml spoons → "½ tsp"`; `100 ml spoons → "100 ml"`.
  - `2.3 g smoked paprika (g_per_tsp 2.3) spoons → "1 tsp"`; same metric → `"2.5 g"`.
  - `5 g ginger, g_per_tsp null, spoons → { text: "5 g", flag: "no-spoon-conversion" }`; `400 g, g_per_tsp null, spoons → { "400 g", null }`.
  - `{ amount: null, original: "1 tsp" } ×2 → { "1 tsp", "not-metric" }` in both modes.
  - `no_scale 1 piece lemon ×3 → "1"`; `to taste ×3 → ""`.
