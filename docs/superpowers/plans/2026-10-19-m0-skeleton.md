# M0: Skeleton, first deploy, MCP from the phone — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the template placeholder with a read-only recipe app (format v1, seeded
recipes, JSON API, unstyled React list/detail, `/mcp` with two read tools), deploy it to
the NAS, and prove claude.ai on a phone can reach `/mcp` through Cloudflare Access.

**Architecture:** One Starlette process serves `/healthz`, `/api/*`, `/mcp` (an
`mcp` 2.x `MCPServer`, stateless JSON) and the built React SPA from `STATIC_DIR` with an
`index.html` fallback. Recipes are one `recipe.json` per folder under
`$APP_DATA_DIR/recipes/<side>/<slug>/`, read from disk on each request (no index yet).
Example recipes are bundled in the package and copied into an empty data dir at startup.

**Tech Stack:** Python 3.12, uv, Starlette 1.9, pydantic 2, mcp 2.3, pytest, ruff;
Node 24 (CI) / 22 (local), Vite 8, React 19, react-router 8, TypeScript, Vitest +
Testing Library + jsdom.

**Spec:** `docs/plan.md` (milestone M0 and Decisions), `docs/requirements-v1.md`, and
the conventions in `CLAUDE.md`.

## Global Constraints

- Listen on `0.0.0.0:8080`; `GET /healthz` → 200 `{"status":"ok","version":"<APP_VERSION>"}`.
- Writes only to `/data` and `/tmp`; the container runs `read_only: true`, uid/gid 1000, `cap_drop: [ALL]`.
- Config only from TOML at `$APP_CONFIG`; every setting in both `config.example.toml` (with comment) and `Settings`, same default.
- Dirs inside the container come from env vars with fixed defaults: `APP_DATA_DIR` (default `/data`), `STATIC_DIR` (unset = no frontend). No host paths in code.
- No secrets in this milestone; `nas-app.toml` `[secrets] names = []`.
- Logs to stdout/stderr only.
- Never touch the CI template guard, the publish job, its tags, or `image-check`.
- Sides are exactly `food` and `drinks`. Categories: food `mains, sides, desserts, sauces, prep`; drinks `cocktails, mocktails, syrups, prep` (requirement 13).
- Units are metric only: `g`, `ml`, plus `piece`, `dash`, `pinch`, `to taste`. No cups, no tsp/tbsp as stored units (requirement 7).
- Recipe files carry `format_version` (requirement 12); current version is `1`.
- Deploying is a merge to `main`, which needs Serwan's OK. Work happens on branch `claude/peaceful-ptolemy-13s6fp`.

## Review Focus

1. **Read-only container with no `/data` mount** (CI `image-check` runs `--read-only` with only `/tmp` writable): the app must still start and answer `/healthz`; a failed seed copy is a logged warning, not a crash. → Task 2 test `test_seed_failure_is_logged_not_raised`, Task 6 smoke.
2. **Hand-edited, corrupt or newer-format `recipe.json` on the NAS:** the list still loads with that file skipped and a warning logged; `get` returns `None`. → Task 2 tests.
3. **Slug or side path traversal** (`../config`, `%2e%2e`) from the API, the SPA fallback or MCP: 404 / tool error, nothing outside the data or static dir is read. → Tasks 2, 3.
4. **`/mcp` requests arriving through Cloudflare with `Host: laekkert.serwan.me`:** not rejected by the SDK's DNS-rebinding protection (421). → Task 5 test.
5. **Deep-link reload in the browser** (`/drinks/daiquiri`) serves `index.html`, while an unknown `/api/...` path returns JSON 404, not the SPA. → Task 3 tests.
