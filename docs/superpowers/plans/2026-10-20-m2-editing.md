# M2: Editing and timeline — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Recipes can be added, edited, deleted and given marks, ratings, notes and
"Made it" entries in the app. Every recipe has one history (the timeline) with a readable
diff for each edit, and any earlier version can be restored.

**Architecture:** Each recipe folder gains `timeline.jsonl`, with one JSON entry per
line, oldest first. It also gains `versions/NNNN.json`, a full `recipe.json` snapshot
after each content change. All writes go through one atomic-write helper. The store gains
write methods that apply the mark rules and append timeline entries. The diff is computed
when an edit is saved and stored in the entry, so the history never has to re-read old
versions. The rating and the last-made date are derived from the timeline and added to
API responses; `recipe.json` keeps format 1. The frontend gains:

- one editor component, for new and existing recipes, on phone and desktop;
- mark toggles, star rating, "Made it" and a History section on the recipe page;
- the Rating and Recently made sorts.

**Tech Stack:** as M1. No new dependencies on either side: uploads are a raw request
body (no `python-multipart`), and the editor's reordering uses buttons, not a drag
library.

**Spec:** `docs/plan.md` (M2, Storage, Decisions), `docs/requirements-v1.md` (5, 7–18),
the design snapshot in `docs/design/artboards/` (`EditorDesktop`, `RecipeDesktop`,
`RecipePhone`, `Main`, `FoodGridPhone`) and `CLAUDE.md`. The rulings below settle what
those leave open.

## M2 rulings (the spec for what the sources leave open)

**Timeline.** One timeline per recipe, newest first on screen. There are no authors in
the PoC. Every entry records `via` (`"app"` now, `"claude"` from M3) and `at` (UTC, ISO
8601, seconds, `Z`). Entry kinds:

| kind | fields | shown as |
| --- | --- | --- |
| `created` | `version` | "Created this recipe" |
| `baseline` | `version` | "Before the first edit in the app" (see Versions) |
| `edit` | `version`, `changes`, `restored_from` (version or null) | "Edited ingredients and method" + diff lines; a restore reads "Restored the version from 28 Sep" |
| `note` | `text` | "Added a note" + text |
| `rating` | `rating`, `previous` | "Rated it 4.5", or "Changed the rating 4.0 → 4.5" |
| `made` | `rating` (or null), `note` (or "") | "Made it" with optional stars and note |
| `marks` | `added`, `removed` | "Marked it Kid approved", "Took off Try next" |

Every entry also has `id` (12 hex) and `kind`. A `via: "claude"` entry gets the suffix
"· via Claude". Lines that don't parse, and unknown kinds, are skipped with a warning
(the file can be hand-edited on the NAS).

**"Made it"** is a new entry kind, and the "Recently made" sort reads it. One button on
the recipe page opens a small inline form: optional stars, an optional note and "Save".

**Ratings** go from 0.5 to 5 in half stars. The current rating is the latest `rating`
entry or `made` entry that carries a rating (requirement 17). To give a half star, tap a
star to set n; tapping the same star again sets n − 0.5. There is no "clear rating".

**Mark rules** (requirement 15):

- Favourite implies tried. Adding favourite adds tried, and removing tried removes
  favourite.
- Kid approved and Kids rejected exclude each other. Adding one removes the other.
- A *tasting* is a `made` entry or a `rating` entry. A tasting adds tried and clears
  try next, with no separate `marks` entry.
- Mark changes and tastings change `recipe.json` but are not edits: they make no version,
  and restoring a version keeps the current marks.
- The page offers four toggles on both sides: Favourite, Kid approved, Kids rejected and
  Try next. Tried is shown as status only, because a tasting is what sets it. (The
  artboard has no Kids rejected toggle; requirement 15 has the mark, so it gets one.)

**Versions** (requirement 18):

- `versions/0001.json` is written on create.
- Each content change writes the next number and an `edit` entry. A save that changes
  nothing writes nothing.
- Recipes that predate M2 (the seeds, and the four on the NAS) have no versions. Their
  first edit first writes the old state as `0001` plus a `baseline` entry, so it can be
  restored.
- Restoring version k writes k's content as a new version with `restored_from: k`.
  Nothing is erased.
- "Restore this version" is on every `created`, `baseline` and `edit` entry except the
  newest version. It means "the recipe as it was after this entry", per the artboard.
  Confirm text: "Restore the recipe as it was after this change? Later changes stay in
  the history."

**Readable diff.** The diff is a list of `{section, kind, text}`.

- `section` is one of `details`, `ingredients`, `method`, `source`, `tags`, `photo`.
- `kind` is one of `added`, `removed`, `changed`; the UI marks them `+`, `−` and `•`.
- Ingredients are matched by casefolded item. An amount change is "lime juice 25 → 20 ml".
- When the unit changes too, both sides show their unit: "chili flakes 1 tsp → 2.5 ml".
  A row stored as written shows its `original`. The full table is in Task 2.

**Slugs** are made from the name on create. They never change on rename, so links stay
valid. Taken slugs get `-2`, `-3`… and `new` is reserved, because `/:side/new` is the
editor. The side can't change after create.

**Editor.**

- The same form serves New and Edit, with the fields of requirement 5 plus cooking time.
- The desktop layout is `EditorDesktop`. The phone layout is one column with Cancel and
  Save in a fixed bottom bar; each ingredient is a stacked card.
- Drinks use the same form in the dark theme.
- Rows reorder with "Move up" and "Move down" buttons; the artboard's drag handles are
  left for later.
- The unit list is g, ml, tsp, tbsp, piece, dash, pinch and to taste. tsp and tbsp are
  input conveniences, converted on save. With a catalog `g_per_tsp` the amount becomes g;
  without one it becomes ml (1 tsp = 5 ml, 1 tbsp = 15 ml, exact). Stored units stay
  metric (requirement 7).
- A row that came in unconverted (amount null, `original` set) shows "As written: 1 cup"
  and keeps it until an amount is typed.
- Cancel and reload with unsaved changes ask first. A failed save keeps the form and
  shows the error.

**Images and delete.**

- The photo and the source photo are uploaded as soon as they are picked, to
  `POST /api/uploads`. That parks the file in `/data/uploads/`. Save moves it into the
  recipe folder, so Cancel leaves the recipe untouched.
- Replaced images stay in the folder, because older versions refer to them.
- Uploads accept JPEG, PNG, WebP, GIF, AVIF and HEIC up to 20 MiB, checked by their magic
  bytes. Uploads older than a day are removed.
- Delete moves the folder to `/data/trash/<side>/<slug>-<UTC stamp>/` after a confirm.
  Getting a recipe back is a file move on the NAS.
- Seeding skips when the trash holds anything, so deleting every recipe doesn't bring
  the examples back.

## Global Constraints

- All M0/M1 constraints still hold: port 8080, writes only under `/data` and `/tmp`, config only from `$APP_CONFIG`, no secrets, no host paths, logs to stdout. M2 adds no settings.
- `recipe.json` stays `format_version: 1`; no stored recipe field is added. `rating` and `last_made` are computed, API-only fields.
- Every write is atomic: temp file `.tmp-<hex>` in the target's own folder, `fsync`, `os.replace`; the temp file is removed if anything fails. `timeline.jsonl` is rewritten whole the same way.
- API handlers stay `async def` and call the synchronous store without awaiting in between, so writes are serialised by the event loop (one uvicorn worker). Never make a write handler a sync def, which Starlette would run in a thread pool.
- Write routes accept only `Content-Type: application/json` (uploads: only the image types listed above) and answer 415 otherwise; bad JSON → 400; validation → 400 `{"error": "<sentence>"}`; unknown recipe → 404; a failed disk write → 503 `{"error": "could not save; nothing was changed"}`.
- Sides `food`, `drinks`; categories food `mains, sides, desserts, sauces, prep`, drinks `cocktails, mocktails, syrups, prep`. Stored units `g`, `ml`, `piece`, `dash`, `pinch`, `to taste`.
- Every interactive element at least 44 × 44 px; every icon-only control has an `aria-label`; toggles use `aria-pressed`. Breakpoint `(min-width: 768px)`; no horizontal scroll at 360 px.
- Copy is plain and British ("Favourite", "Kids rejected", "Made it"). Dates show as "12 Oct", with the year when it isn't the current one, in the browser's time zone.
- MCP stays read-only in M2 (`add_recipe` and `edit_recipe` are M3), but the store's write methods take `via` so M3 can pass `"claude"`.
- Work on `claude/peaceful-ptolemy-13s6fp`. Merging to `main` deploys and needs Serwan's OK.

## Review Focus

1. **Cross-site writes through Cloudflare Access cookies.** A form on another site POSTs `text/plain` or urlencoded to a write route, or sends a `no-cors` fetch. The answer is 415 and nothing is written. Only preflighted requests (JSON, image types, DELETE) can write, and the app sends no CORS headers. → Task 4 test `test_write_routes_reject_simple_content_types`.
2. **A failed write** (the read-only `/data` in CI `image-check`, a full disk, a crash mid-save). The old `recipe.json` and `timeline.jsonl` are byte-for-byte intact, no `.tmp-*` file is left, and the API returns 503 JSON, not a stack trace. → Task 1 test `test_atomic_write_failure_leaves_original`, Task 4 test `test_write_failure_is_503`.
3. **Hand-edited or partial history on the NAS.** This covers a corrupt `timeline.jsonl` line, an unknown kind, a deleted `versions/0002.json`, and a recipe with no versions or timeline at all. List, detail and history still load, with bad lines skipped. Restoring a missing version is a 404. The first edit of a pre-M2 recipe writes a baseline. → Task 1 test `test_bad_lines_are_skipped`, Task 3 tests `test_first_edit_of_legacy_recipe_writes_baseline` and `test_restore_missing_version_is_none`.
4. **Hostile uploads and image names.** This covers HTML or SVG bytes labelled `image/png`, a 25 MiB body, and a draft whose `image` is `../../daiquiri/recipe.json`, `recipe.json` or a name that is neither in the recipe folder nor in uploads. The answers are 415, 413 and 400, and nothing is moved from outside `/data/uploads/`. → Task 3 test `test_draft_image_must_be_upload_or_own_file`, Task 4 tests `test_upload_rejects_non_images`, `test_upload_rejects_oversize`.
5. **Losing work in the editor on a phone.** This covers Cancel, a reload or a tab close with unsaved changes, a save that fails on the server, and a double tap on Save. A confirm comes before discarding; the form stays filled with the error in an alert; Save is disabled while saving, so only one request goes out. → Task 7 tests `cancel with changes asks first`, `failed save keeps the form and shows the error`, `save sends one request on double tap`.

### Task 2: Readable diff and draft normalisation

**Files:**
- Create: `src/app/recipes/diff.py`, `src/app/recipes/drafts.py`
- Test: `tests/test_diff.py`, `tests/test_drafts.py`

**Interfaces:**
- Consumes: `Change` (Task 1); `Recipe`, `Ingredient`, `Source`, `Unit` (model); `Catalog.g_per_tsp` (M1).
- Produces:
  - `describe_changes(old: Recipe, new: Recipe) -> list[Change]` in `app.recipes.diff`; an empty list means no content change. It ignores `marks`, `format_version`, `slug` and `side`.
  - In `app.recipes.drafts`:
    - `DraftIngredient` is `Ingredient` with `unit: Unit | Literal["tsp", "tbsp"]`.

    - `to_recipe(draft: RecipeDraft, *, side: Side, slug: str, marks: list[Mark], catalog: Catalog) -> Recipe`. It raises `ValueError` with a sentence.
    - `slugify(name: str) -> str`.

Diff text (amounts via `f"{x:g}"`, or `original` when the amount is null):

| change | section / kind | text |
| --- | --- | --- |
| name, category, servings, time | details / changed | `name “Dal” → “Red lentil dal”`, `category mains → sides`, `servings 4 → 6`, `time 20 → 25 min` (`no time` when null) |
| same item, same unit, new amount | ingredients / changed | `lime juice 25 → 20 ml` |
| same item, new unit | ingredients / changed | `chili flakes 1 tsp → 2.5 ml` |
| same item, new note / no_scale | ingredients / changed | `lime juice: note “” → “fresh”`, `lemon: don't scale on` / `off` |
| added / removed item | ingredients / added, removed | `20 ml lime juice (fresh)` (note in brackets when set; `salt, to taste` for to taste) |
| only the order changed | ingredients / changed | `ingredients reordered` |
| steps (`difflib.SequenceMatcher` opcodes) | method / added, removed, changed | `step 3: <text>` with the new number (old number for removed), text cut to 80 chars with `…` |
| source url / photo | source / changed | `link changed`, `link added`, `link removed`, `source photo replaced` / `added` / `removed` |
| tags | tags / added, removed | `“batch cook”` |
| image | photo / changed | `photo added`, `photo replaced`, `photo removed` |

Draft rules, applied by `to_recipe` in this order:

- Strip `name`, `item`, `note`, `original` and each step.
- Drop ingredient rows that are entirely blank: no item, no amount, no note and no
  original.
- Drop blank steps.
- Tags: strip, collapse inner spaces, lowercase, then de-duplicate keeping order. Drop
  empty tags.
- Convert tsp and tbsp: t = amount (tsp) or amount × 3 (tbsp).
  - With a catalog `g_per_tsp`: unit g, amount t × g_per_tsp, rounded to 1 decimal
    below 10 and to a whole number from 10.
  - Without one: unit ml, amount t × 5.
  - A tsp or tbsp row with no amount is an error: `Ingredient 3 needs an amount in tsp`.
- `source.url` must start with `http://` or `https://`, otherwise
  `The source link must start with http:// or https://`. A source with neither url nor
  photo becomes `null`.
- Other errors come from pydantic, rephrased as one sentence: `Give the recipe a name`,
  `Add at least one ingredient`, `Ingredient 2 needs a name`,
  `Ingredient 2 needs an amount in g`, `Category for drinks must be one of cocktails,
  mocktails, syrups, prep`.

`slugify`:

1. Map `æ→ae ø→o œ→oe ß→ss ł→l đ→d`, apply NFKD, drop combining marks and keep ASCII.
2. Lowercase, turn runs of non-alphanumerics into `-`, trim the dashes and cut to 60
   characters at a dash.
3. An empty result becomes `recipe`.

### Task 4: Write API and derived fields

**Files:**
- Modify: `src/app/api.py`, `src/app/main.py`
- Test: `tests/test_api_writes.py`, `tests/test_api.py`

**Interfaces:**
- Consumes: Task 3's store and `UploadStore`.
- Produces (every JSON body is the detail shape unless stated):
  - `GET /api/recipes?side=` summaries gain `rating: number | null` and `last_made: string | null`. `GET /api/recipes/{side}/{slug}` gains the same two fields.
  - `GET /api/recipes/{side}/{slug}/timeline` → `{"entries": [Entry…] newest first, "current_version": int | null}`.

  - `DELETE /api/recipes/{side}/{slug}` → 204.
